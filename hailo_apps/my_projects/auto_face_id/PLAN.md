# План: определение входа через дверь

Этот файл служит рабочим планом для этапа, где существующая система
`person detection` + `person tracking` + `face recognition` должна фиксировать
факт входа человека в помещение.

На этом этапе реализуется только событие `ENTER`. Логика выхода пока не
рассматривается.

## Что уже есть

- [x] Детекция человека (`person`)
- [x] Трекинг человека (`person_track_id`)
- [x] Распознавание лиц
- [x] Связывание `person_track_id` с постоянной личностью (`global_id`, `person_1`,
      `person_2` и т.д.)
- [x] HTTP-уведомления через `--notify-url`
- [x] Debug MJPEG overlay в `person_face_id.py`

## Цель

Добавить независимый механизм фиксации прохода через дверь:

- определить, что человек действительно вошел в помещение;
- связать вход с известной личностью, если `global_id` уже определен;
- отправить событие `ENTER person_N` или `ENTER Unknown`;
- исключить повторный подсчет одного и того же прохода;
- не зависеть от роста человека, размера bbox и небольших колебаний детектора.

## Геометрия

На кадре задаются две виртуальные линии:

```text
        ДВЕРЬ

-------------------- LINE_A

      ЗОНА ПРОХОДА

-------------------- LINE_B

        КАМЕРА
```

Событие входа фиксируется, когда один и тот же `person_track_id`
последовательно пересекает линии в правильном порядке:

```text
LINE_A -> LINE_B -> ENTER
```

Для отслеживания используется нижняя центральная точка bbox:

```text
foot_x = (x1 + x2) / 2
foot_y = y2
```

## Принятые решения

- [ ] Использовать `person_track_id` как основной ключ состояния прохода.
- [ ] Использовать `global_id` только как дополнительную информацию для события.
- [ ] Считать `ENTER` отдельным событием, не равным текущему событию
      `recognized/enrolled`.
- [x] Оставить `visits_count` как счетчик новых распознанных `track_id`.
- [x] Добавить отдельный счетчик `entered_times`, который показывает, сколько раз
      человек подтвержденно вошел через дверь.
- [ ] Хранить runtime-состояние проходов в памяти. Персистентное хранение событий
      добавить отдельным этапом, если понадобится история входов.

## Конфигурация

Добавить CLI-параметры в `person_face_id.py`:

- [ ] `--entry-line-a-y` - координата `LINE_A` в нормализованных координатах кадра
      `0.0..1.0`.
- [ ] `--entry-line-b-y` - координата `LINE_B` в нормализованных координатах кадра
      `0.0..1.0`.
- [ ] `--enable-entry-detection` - включает логику входа.
- [ ] `--entry-line-margin` - небольшой гистерезис/мертвая зона вокруг линии,
      чтобы bbox-jitter не создавал повторные пересечения.
- [ ] `--entry-track-ttl-seconds` - время очистки состояния пропавших треков.
- [ ] `--entry-event-cooldown-seconds` - защита от повторного события для того же
      `person_track_id`.
- [ ] `--entry-min-frames-between-lines` - опциональная защита от мгновенного
      ложного пересечения обеих линий в одном скачке детектора.

- [ ] возвращает `EntryEvent` только один раз для прохода.

## Алгоритм

- [ ] Для каждого кадра брать только `person_detections`.
- [ ] Для каждого `person_detection` получить `person_track_id`.
- [ ] Перевести bbox в нормализованные или pixel-координаты, но внутри алгоритма
      использовать один формат стабильно.
- [ ] Вычислить `foot_x`, `foot_y`.
- [ ] Обновить состояние `EntryDetector` для этого `track_id`.
- [ ] При первом пересечении `LINE_A` перевести state в `crossed_a`.
- [ ] При последующем пересечении `LINE_B` из state `crossed_a` сгенерировать
      `ENTER`.
- [ ] После `ENTER` перевести state в `entered`, чтобы дальнейшие движения внутри
      помещения не считались повторно.
- [ ] Периодически очищать состояния треков, которые давно не видны.

## Защита от ложных срабатываний

- [ ] Не генерировать событие по одной линии.
- [ ] Не генерировать событие, если порядок `LINE_B -> LINE_A`.
- [ ] Использовать гистерезис `entry_line_margin` вокруг линий.
- [ ] Игнорировать повторное пересечение `LINE_B`, если state уже `entered`.
- [ ] Не сбрасывать state немедленно при кратковременной пропаже детекции.
- [ ] Сбрасывать state только по TTL, когда `track_id` действительно исчез.
- [ ] Добавить cooldown для одного `track_id`.

## Связь с распознаванием личности

- [ ] На момент `ENTER` прочитать:
      `track_to_global_id.get(person_track_id)` и
      `track_to_label.get(person_track_id, "Unknown")`.
- [ ] Если личность уже известна, событие должно быть:
      `event="enter"`, `global_id=<uuid>`, `label="person_N"`.
- [ ] Если личность еще неизвестна, событие должно быть:
      `event="enter"`, `global_id=None`, `label="Unknown"`.
- [ ] Если личность распознана после `ENTER`, на первом этапе не переотправлять
      событие. Возможное улучшение следующего этапа: delayed-resolution event.

## Тестирование

Добавить unit tests для чистого `EntryDetector`:

- [ ] `LINE_A -> LINE_B` генерирует ровно один `ENTER`.
- [ ] `LINE_B -> LINE_A` не генерирует `ENTER`.
- [ ] Движение внутри зоны между линиями не генерирует событие.
- [ ] Колебание вокруг одной линии не генерирует `ENTER`.
- [ ] Повторное движение после `entered` не генерирует второй `ENTER`.
- [ ] Краткая пропажа трека не сбрасывает состояние до TTL.
- [ ] После TTL состояние очищается.

Проверить вручную на видео/камере:

- [ ] Человек остановился между линиями.
- [ ] Человек сделал шаг назад.
- [ ] Человек вошел до завершения распознавания лица.
- [ ] Известный человек вошел после распознавания.
- [ ] Несколько людей проходят рядом.
